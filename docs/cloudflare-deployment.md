# Автоматическое Обновление

Существующий Worker: `action-cards`. Репозиторий: `ilyakaltsou-a11y/action-cards`.

Cloudflare Workers Builds публикует изменения из `main` после успешных проверок.
Не создавайте другой Worker или новое хранилище: это изменит адрес или доступ к карточкам.

## Однократное Подключение

1. Откройте существующий Worker в Cloudflare, раздел **Settings → Builds**.
2. Подключите GitHub и выберите только репозиторий `action-cards`.
3. Production branch: `main`. Root directory: `/`.
4. Build command: `npm run build`. Deploy command: `npm run deploy`.
5. Используйте Node.js 22 или новее (для сборки можно задать `NODE_VERSION=22`).
   Проект использует `pnpm@11.19.0` и существующий `pnpm-lock.yaml`; Cloudflare определяет менеджер по `packageManager`. В GitHub Actions зависимости ставятся через `pnpm install --frozen-lockfile`.
6. Не включайте публикацию других веток с production-хранилищем. Для preview нужна отдельная KV namespace.
7. Проверьте текущую привязку `CARDS_KV`: `9fe16fa356cd49b6ad39e0e4851f4f36`.
8. Секреты `OPENAI_API_KEY` и `DEEPSEEK_API_KEY` остаются в настройках Worker. Не добавляйте их в репозиторий или журналы сборки.
9. Запустите первую сборку и дождитесь успешного Deployment.

Дальше push в `main` запускает проверки и обновление сайта. Неудачная проверка останавливает публикацию.
GitHub Actions дополнительно запускает тот же набор проверок, но не получает доступ к личным данным или Cloudflare.
GitHub push без подключённого Workers Builds не публикует приложение.

## Возврат

В Cloudflare **Deployments** можно вернуть предыдущую успешную публикацию. Чтобы следующий push не вернул проблемный код,
сохраните исправление или возврат новым коммитом Git, не стирая историю.
Версия кода и пользовательские данные независимы: возврат кода не восстанавливает карточки.

## Резервные Копии

В приложении: меню вверху справа → **Резервные копии**.

- Статус под названием показывает сохранение на сервере, ожидание отправки или отсутствие связи.
- Последние изменения повторно отправляются при восстановлении связи и каждые 30 секунд, пока страница открыта.
- Браузер сохраняет профиль одним атомарным JSON и до семи предыдущих копий.
- Сервер перед первой заменой профиля за день сохраняет старое состояние в один из семи суточных слотов KV. В один день слот не перезаписывается.
- Серверные копии появляются после установки этой версии, а не задним числом. Они находятся в той же KV, поэтому не защищают от удаления самой namespace.
- **Скачать копию** сохраняет карточки, папки, прогресс, активность и оба словаря. Созданные пользователем картинки в `/images/` и `assets/ai/` встраиваются в файл. Стартовые картинки остаются ссылками на поставляемые с приложением ресурсы; внешние картинки остаются внешними ссылками.
- Лимит файла: 64 МБ; одна встроенная картинка — до 8 МБ в base64. Ошибка загрузки картинки отменяет скачивание вместо создания неполной копии. При восстановлении встроенные картинки сохраняются отдельно в KV, а не в JSON профиля.
- Восстановление по дате или из файла добавляет данные к текущему профилю, не удаляя новые карточки. Перед восстановлением сохраняется локальная копия.

Скачанный файл содержит личные данные и код профиля. Храните его приватно, не в публичном GitHub.
Код профиля по-прежнему служит ключом доступа: это не полноценная авторизация с паролем.

Официальная документация: https://developers.cloudflare.com/workers/ci-cd/builds/configuration/
